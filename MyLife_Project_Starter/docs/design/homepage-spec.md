# 首页 UI 方案

状态：P0 高保真实施规格；尚未交付或验收实际页面稿。方向延续深色 Hero + 暖白内容、现代写实材质与空间层次，不改为数据密集 Dashboard 或游戏场景。

## 1. 目标与规范引用

首页建立 MyLife 品牌印象，让用户直接进入衣橱，并查看自己最近的活动。布局数值只引用[响应式规范](responsive-guidelines.md)，组件样式引用[组件规范](component-spec.md)，色彩引用 [Design System](design-system.md)，动效引用 [Motion System](motion-system.md)。不在本页另设颜色/圆角/曲线。

## 2. 页面结构与主题

| 区块 | 内容与优先级 | 视觉 / 实施约束 |
| --- | --- | --- |
| 顶部导航 | MyLife. 字标、已开放模块入口、账户菜单 | Dark；内容容器与正文对齐；完整菜单在 lg 起显示；向下滚动仍保持实色 Dark，不以透明叠加保证可读性 |
| Hero | 主标题、简短说明、一个主 CTA、一个媒体主体 | Dark；按响应式规范分栏/上下排；使用 hero 排版角色与 lg Button |
| Personal Space | 第一阶段衣橱入口、功能说明 | Light 区；媒体区可 Dark；仅一张已开放模块时使用特色卡，不为凑三列虚构模块 |
| Recent Activity | 当前用户最近使用/更新的衣物、形象或穿搭 | Light；最多 6 项，按更新时间倒序；卡片复用已有组件；更多内容回到相应模块 |
| Footer | 版本、隐私与基础说明 | Light；次级文字；文档未对应实际页面时不放空链接 |

模块卡内部允许明暗媒体交错，但标题/操作需落在明确主题的实色内容区。装饰对象仅放在媒体区域；不把页面导航做成漂浮物件。

## 3. 文案和动作基线

保留原英文文案方向，最终语言与品牌排版在 Design System 的 D-01 / D-04 中确认：

- 品牌：MyLife.
- 主标题：Your life, beautifully organized.
- 辅助文案：A personal space for everything that matters.
- 已登录主 CTA：Enter Wardrobe（中文语义“进入衣橱”），直接进入衣橱。
- 未登录主 CTA：Enter Wardrobe，先进入登录，成功后回到衣橱；不能请求或露出私有活动。
- Explore your space 暂不作为并列主 CTA；未来模块达到多个后再评审是否用于滚动定位 Personal Space。
- 最近活动空状态：说明尚无内容，主操作“添加第一件衣物”进入衣橱添加流程。无权限或网络错误不能伪装成空状态。

本基线不更改既有“登录后进入个人首页”的常规旅程；带明确衣橱目的地的入口在登录后恢复该目的地。登录路由和安全会话仍由产品/架构定义，不由视觉稿决定身份授权。

## 4. 状态设计矩阵

| 状态 | 页面表现 | 恢复 / 交互 |
| --- | --- | --- |
| 未登录 / 公开入口 | 展示品牌与模块概览，活动区显示登录提示，无姓名/照片等私人数据 | CTA 登录后恢复目标；账户按钮为登录 |
| 会话检查中 | Hero 与公共内容可见；账户/活动各自占位，不阻塞主视觉 | 确认会话后局部替换，避免跳版 |
| 已登录有数据 | 用户菜单 + 自己的最近活动 | 衣橱入口立即可用，活动链接到相应详情 |
| 首次使用 | 有明确解释的活动空态 | 添加第一件衣物；不展示虚构“你的历史” |
| 活动加载 | 维持最终卡片比例的 Skeleton | 只该区 aria-busy，不遮住 Hero 或导航 |
| 活动读取失败 | 区块内错误 + 重试 | 已开放模块入口继续可用 |
| 图片读取失败 | 等比例失败占位 | 可重新加载图片；卡片文字与其他操作仍可用 |
| 会话失效 | 清除当前视图中的私有内容，给出重新登录入口 | 只保存安全的返回目的地；不暴露缓存个人照片 |
| 模块未开放 | 基线不展示未来模块；若 D-04 确认展示，使用“筹备中”静态卡 | 无假按钮，不弹“功能不存在” |
| 移动菜单展开 | Sheet + 遮罩 + 正确主题和焦点 | 可关闭，路由选择后收起并管理焦点 |
| reduced motion | 完整静态构图与必要反馈 | 所有入口依旧可用，无视差与倾斜 |

首页最近活动只展示后端已授权的数据；P0 原型用明确标注的演示数据，不能借文案设计承诺尚未确定的字段/API。

## 5. 高保真制作与交接顺序

1. 使用 Design System 执行基线制作 Light / Dark 组件样张；先核对文字、输入、主按钮、选中与错误状态，不各画一套组件。
2. 先完成 1440px 首页正常态，再做 768px 与 390px 独立排版；复用同一结构检查 320px 与所有断点边界。画板不是 CSS 断点的第二套来源。
3. Hero 先用有来源记录的写实静态素材样张定构图，再分层制作装饰进入与媒体反馈；移动另给裁切和主体安全区域。Hero 具体主体属于 D-03 待审美确认，不生成新风格。
4. 补第 4 节所有状态，以及 hover、focus、菜单打开、长文本、图片失败。截图需能看见真实字段和操作文案，不用一排灰块代替错误状态稿。
5. 制作可点击原型：主 CTA → 登录/衣橱目标、模块入口、菜单开关、活动重试；返回路径、焦点和 reduced motion 都有注释。业务目标可用明确标识的原型占位，不实现真实业务。
6. 提交交接包：画板、组件/Token 映射、素材清单与授权、桌面/移动裁切、动效模式和降级、状态矩阵、D-01 至 D-06 决策结果。
7. 按[设计验收](design-acceptance.md)评审后进入 P1。首页完成不代表衣橱关键流程稿、安全边界与 AI 能力评审完成。

不得为表现“3D Editorial”默认引入实时 3D、Three.js、自动播放大视频、Low-poly、卡通、浮岛或自由漫游。
