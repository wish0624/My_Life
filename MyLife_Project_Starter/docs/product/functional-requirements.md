# 第一阶段功能需求：衣橱与虚拟穿搭

## 1. 登录与用户隔离
用户通过公网入口进入，选择/识别身份，回答管理员配置的问题。答案由服务端验证，成功后建立会话。管理员可创建、停用用户身份，配置或重置每个用户的验证问题与答案。

安全要求：
- 答案仅在服务端验证；不得写入前端代码、公开配置或日志。
- 答案使用带盐密码哈希存储，不保存明文。
- 对错误尝试限流，必要时临时锁定。
- 使用 HTTPS 与安全 Cookie 会话。
- user_id 从服务端会话取得，不信任客户端传入的 user_id。
- 所有查询、更新、删除均校验数据归属。
- 管理员与普通用户权限分离。
- 问题答案属于较弱认证方式；若未来管理敏感信息，应升级认证机制。

## 2. 衣物数字化
添加方式：上传图片（文件选择、拖拽）；粘贴网址并尝试提取商品主图和元数据。网址解析失败时允许手动上传或填写。

图片处理：保存原图；生成标准化处理图；支持背景去除、主体裁剪、居中和尺寸规范化；用户确认或调整；保留处理状态、错误原因并允许重试。

建议属性：名称、分类、主/辅颜色、风格标签、季节、品牌（可选）、来源链接（可选）、原图、处理图、创建/更新时间。自动识别结果必须允许用户修改。

## 3. 虚拟真人形象
第一版：上传人物参考照片；可选填写身高、体型等参数；生成候选形象；预览、选择、确认并保存；支持重新生成和替换；保存形象版本及来源引用。
第一版以 AI 生成图像形象为主，不承诺可控 3D 网格、骨骼或精确人体测量。

隐私：明确告知照片用途和第三方处理情况；默认仅本人可见；提供删除原图、生成图及相关数据的能力；未经明确授权不得将照片用于其他用途或训练。

## 4. 虚拟穿搭 / Outfit Studio
流程：选择形象 → 选择衣物 → 检查组合 → 提交生成 → 查看进度 → 预览 → 保存/重试/删除/创建版本。
第一版优先支持上装、下装、连衣裙等主要类别。复杂叠穿、配饰和多件同时生成按模型能力逐步增加。不得假设单件试穿模型天然支持任意多件组合；按选定模型/API能力设计适配层。
生成图仅为视觉模拟，不代表真实尺码、版型或合身度。

## 5. 穿搭管理
保存穿搭方案，记录使用的形象、衣物、生成结果；支持收藏、删除、历史查看和重新生成。记录模型/API、任务状态和时间，便于排错与成本管理。

## 6. 非功能需求
响应式；图片按需加载；关键操作可键盘访问；支持减少动态效果；业务模块独立；AI 服务通过后端适配层接入；日志不记录答案或敏感图片内容。
