# 开发路线与阶段验收

## P0：产品与设计准备（当前）

交付：产品概述、功能需求、用户旅程、可执行 Design System、首页方案、关键流程稿、架构草案。验收：视觉方向无歧义，关键设计可交接，技术与安全边界明确；详见 [Definition of Done](definition-of-done.md)。

本轮范围：设计系统及关联文档完善，不初始化 React、不编写业务、不调用 AI 服务、不生成或宣称已经验收高保真画稿。

### 本轮已形成的文档基线

- [Design System v1.1](../design/design-system.md)：双主题语义 Token、排版、公共尺寸、阴影、实际叠层与接入契约。
- [响应式规范](../design/responsive-guidelines.md)：明确断点、容器、栅格和工作台布局。
- [组件规范](../design/component-spec.md)：尺寸、变体、交互、异常与键盘行为。
- [Motion System](../design/motion-system.md)：动画模式、触发、中断、降级与预算。
- [首页规范](../design/homepage-spec.md)：内容、CTA、状态矩阵与高保真实施顺序。
- [设计验收](../design/design-acceptance.md)：一致性标准、对比度证据与后续检查矩阵。

### P0 剩余任务

1. 审阅 Design System 的 D-01 至 D-06：字体/字标、主题样张、Hero 素材、文案/未来模块、动效/图标、工作台主题比例。
2. 制作 Light / Dark 组件状态样张，验证全部适用状态，不能只展示 default。
3. 按首页规范完成高保真与交互原型、素材授权记录及移动裁切；执行设计验收。
4. 补衣橱列表、添加衣物、形象创建、试穿工作台的关键流程稿及异常状态。
5. 收敛首版试穿组合、参考照片要求、候选数量、失败兜底和费用边界；完成 AI 能力验证计划。设计稿不超前承诺未经验证能力。
6. 评审身份识别、凭据重置、会话、管理员及真人照片处理/删除策略；当前已有照片隐私需求，不能等未来再处理。
7. 对齐生成任务状态、版本/文件生命周期、数据关系与最小 API 契约；本轮组件中的状态名称只是展示映射需求。
8. 记录评审结论、责任人与验收证据；完成后才结束 P0。

## P1：前端基础与首页

- 初始化 React + TypeScript + Vite 项目，锁定依赖版本。
- 按[前端架构](../architecture/frontend-architecture.md)实现 Token、字体、基础组件、主题区域与 Motion 封装。
- 先建立双主题组件状态样张，再完成响应式首页、导航和模块入口。
- 验收：通过设计验收矩阵及 Motion 预算；有桌面/平板/手机和 reduced motion 证据，关键交互完整。

## P2：后端与多用户

- FastAPI、PostgreSQL、对象存储。
- 管理员创建用户与设置问题/答案。
- 登录会话、限流、数据归属校验。
- 远程测试真实会话前提供 HTTPS 测试环境与安全 Cookie，不能等待 P5 才验证。
- 验收：至少两个测试用户；用户 A 无法读取、修改、删除用户 B 的任何数据或文件。

## P3：衣物数字化

- 图片上传、网址解析兜底、原图/处理图存储。
- 背景移除、属性识别、人工编辑。
- 按 P0 定义的边界落最小 AI Provider Adapter，覆盖本阶段图像处理；不把所有适配推迟到 P4。
- 验收：上传、处理、失败重试、编辑和删除闭环完成。

## P4：虚拟形象与试穿

- 虚拟形象创建与管理。
- 扩展 AI Provider Adapter，接入已验证的形象/试穿能力。
- Outfit Studio、生成任务状态、结果保存。
- 验收：选择形象和衣物到生成、预览、保存形成闭环；隐私与成本控制通过检查。

## P5：正式部署与扩展

- 正式域名、HTTPS、Docker 部署。
- 备份、日志、监控、错误处理。
- 安全与移动端验收。
- 验收：朋友可通过公网访问，无需源码；账号隔离测试通过。

## 当前不应提前做

- 不一次性实现所有未来生活模块。
- 不先做复杂 3D 场景。
- 不在 API 方案未验证前训练模型。
- 不在多用户权限未通过测试前开放真实用户数据。
