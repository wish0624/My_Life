# Definition of Done

本清单用于对应阶段的验收；P0 文档完成不等于页面、业务或上线验收已通过。具体视觉数值只引用[设计验收](../design/design-acceptance.md)，不得在这里另定义阈值。

## P0 设计交付

- [ ] 已确认方向与新增执行基线分开记录，Design System 的 D-01 至 D-06 有评审结果或明确保留项。
- [ ] 颜色/排版/形状、响应式、组件状态、Motion 各有唯一规范来源，引用有效，没有互相覆盖的数值。
- [ ] 首页高保真与关键状态原型齐全，按首页规范交接素材与裁切。
- [ ] 衣橱列表、添加衣物、形象创建、试穿工作台有关键流程稿，不能只验首页。
- [ ] 产品/AI 能力、身份/隐私、安全与任务数据契约达到后续实施所需的明确度；这些不能用设计稿代替。

本次设计文档修订的静态检查记录见[设计验收证据](../design/design-acceptance.md)。未完成的画稿、交互与真实设备检查继续保留未勾选状态。

## 页面设计与体验（P1 起）

- [ ] 主要用户任务可独立完成；移动端没有缺失关键操作。
- [ ] 通过设计验收的双主题、视口矩阵、所有适用交互与异常状态检查。
- [ ] 使用规范 Token、同类组件、图片比例/裁切/失败占位；没有页面私有颜色或重复组件。
- [ ] 键盘焦点、读屏命名、弹层焦点恢复、文字放大与重排通过检查。
- [ ] 动效符合命名模式、性能预算，支持系统/站内减少动态效果。
- [ ] 提供截图、设备与浏览器记录；组件/页面差异可追踪，阻断问题关闭。
- [ ] 已确认审美决策对应实际实现；未批准例外不得悄悄变成新标准。

## 工程与业务（适用阶段）

- [ ] TypeScript 类型明确，无不必要的 any。
- [ ] API 错误有处理且用户可恢复，关键任务状态与后端真实契约一致。
- [ ] 对关键路径运行有意义的测试；纯文档修订执行链接/引用/一致性检查，不声称业务测试通过。
- [ ] 权限在服务端校验，双用户隔离验证完成。
- [ ] 不泄露密钥、验证答案或私人图片；满足[安全清单](../architecture/security-checklist.md)。
- [ ] 日志、性能、成本与恢复策略达到当前发布范围要求。
